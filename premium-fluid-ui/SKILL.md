# Premium Fluid UI - Engineering Skill (v1.9.2)

**Objective:** enforce a measurable size/spacing/typography/layout contract while maintaining the designer's approved visual identity across all screens-even when the project was built **Desktop-First** on a large monitor (`1920x1080` or `1600x900`)-by applying a **Two-Tier Responsive Architecture**:

- **Tier 1 - Smaller Computer Screens (`>= 1024px` width, including `1440x900`, `1366x768`, `1280x720`, and `1024x600`):** preserve the **exact desktop layout, column counts, header links, floating overlay positions, and side-whitespace framing (`~13.5vw` empty margin on both right and left sides)** by converting hardcoded desktop `px` dimensions to `rem` and applying 2D proportional scaling (`min(width-ratio, height-ratio)`).
- **Tier 2 - Tablet & Mobile Portrait/Landscape (`< 1024px` width):** restore `100%` readable root font size and apply **structural reflow** (collapsing secondary header CTAs into a mobile drawer, stacking floating overlay cards cleanly, and switching multi-column grids to 1 column on narrow phones or a compact 2-column split on mobile landscape).

## Non-negotiable rules

0. **STRICT DESKTOP DESIGN & COLUMN-COUNT LOCK (NO UNPROVOKED MUTATIONS).**
   - **Never alter the base desktop design, layout topology, or column count on computer screens (`>= 1024px`):** if a section has a 3-card grid (`grid-cols-3`) or 4-card grid (`grid-cols-4`) on desktop, it MUST remain 3 cards (or 4 cards) per row across ALL computer screens (`1920px`, `1536px`, `1440px`, `1366px`, `1280px`, and `1024px`). **NEVER turn a 3-card desktop grid into 2 large cards, and NEVER replace explicit desktop column counts (`lg:grid-cols-3`) with `auto-fit / minmax()` that drops columns on smaller PC monitors.** Instead, use `repeat(3, minmax(0, 1fr))` (`grid-cols-1 lg:grid-cols-3 min-w-0`) and let the Tier 1 proportional `rem` scaling shrink the 3 cards together so all 3 stay side-by-side.
   - **STRICT DESKTOP HEADER LOCK (`>= 1024px`):** NEVER collapse the Desktop Header/Navbar into a Hamburger or Tablet menu at `1024px`, `1152px`, `1280px` (`xl:`), `1366px`, or `1536px` (`2xl:`). All desktop navigation links and header action buttons MUST remain visible on all computer screens (`>= 1024px`, using `hidden lg:flex`, NEVER `hidden xl:flex` or `hidden 2xl:flex`), and the hamburger button MUST be hidden at `>= 1024px` (`lg:hidden`, NEVER `xl:hidden`). If the header is tight at `1024px-1280px`, use fluid gaps (`gap: clamp(0.5rem, 1.1vw, 1.75rem)`) and `rem` sizing so it scales smoothly with Tier 1 root scaling. Only tablet portrait and mobile (`< 1024px`, or `< 768px`) may use a hamburger drawer.
   - **MANDATORY DESIGN-CONTRACT REPAIR (ALL SEVERITIES):** if measured sizes, spacing, font hierarchy/weight, desktop column count, desktop header visibility, side framing, or mobile reflow deviate from the accepted design contract, the agent MUST correct the deviation even if no text is clipped and even if the finding is P2 / aesthetic. A passing build or absence of overflow does NOT exempt a confirmed visual-sizing violation. Use before/after measurements and screenshots; repair the specific offending property while preserving all approved colors, imagery, typography families, ornamentation, structure, and interactions. If the existing component already conforms, do NOT mutate it. **Do not blanket-convert unverified styles.** See [references/mandatory-conformance.md](references/mandatory-conformance.md).
1. **Two-Tier Desktop-First Preservation vs. Mobile Reflow.** Distinguish between *smaller computer screens* and *handheld mobile/tablet screens*:
   - **On PC / Laptop / Compact Landscape screens (`>= 1024px` width, including `1366x768`, `1280x720`, and `1024x600`):** DO NOT collapse desktop grids into mobile columns and DO NOT drop desktop floating hero cards into stacked flow unless physically impossible. Instead, convert the verified problematic hardcoded `px` lengths (`width`, `min-width`, `padding`, `gap`, `inset`) into `rem` (`px / 16`) and apply the 2D proportional root scale from `assets/desktop-first-scale.css` (`clamp(65%, min(calc(0.15rem + 0.885vw), calc(0.15rem + 1.574dvh)), 125%)`) so the entire desktop design scales harmoniously to the measured CSS viewport. Use the **1536×864 CSS px reference** and calculate the smaller of the width/height factors; document any legibility-floor or accessibility override. The root formula is a calibrated bounded expression, not permission to scale everything blindly. The reference passes when measured computed root font size is approximately 16 CSS px and the 1024×600 desktop still retains the approved grid. Use Playwright computed styles to verify, not just source-code inspection.
   - **Mandatory Desktop Side-Whitespace Framing (`>= 1024px`):** on ALL computer screens (`1024x600`, `1024x768`, `1280x720`, `1366x768`, `1440x900`, `1920x1080`), always preserve **12%-14% (`~13.5vw`) of empty framing space on BOTH the right and left sides** of the main content (`inline-size: 73vw; margin-inline: auto;` or `lg:w-[73vw] lg:mx-auto`). Never rely on `max-w-7xl px-4` alone, which loses all side margins on `1024px-1366px` monitors and slams cards against the screen edges. Full-bleed section backgrounds (`<section>`) may span `100%`, while their *intended framed inner content* stays at `~73vw`; full-bleed heroes, maps, panoramas, navbar/footer, and approved exceptions must be marked/documented rather than forcibly squeezed. Measure both margins against actual CSS viewport width, targeting 12%–14% each with a 0.5 percentage-point measurement tolerance.
   - **On Tablet Portrait & Mobile (`< 1024px` width):** a `320px-390px` phone loses 75% of desktop width, so shrinking alone would make text microscopic. Below `1024px`, reset `html { font-size: 100%; }` and apply **Structural Reflow** (Rule 4).
   - **Anti-Distortion Guards (Icons, Low-Res Text Floor, Card Alignment, Ultra-Wide, Scrollbar):**
     - Convert hardcoded `<svg width="24" height="24">` attributes to `rem`/`em` classes (`w-5 h-5` or `1.25em`) so icons shrink alongside buttons on `1024px` screens.
     - Keep a readability floor (`max(var(--pf-type-body), 12px)` for body and `11px` for micro text) on `1024x600` / `1366x768` so scaled-down Arabic text never blurs on `1dpr` monitors.
     - Enforce equal card heights **when the approved card design calls for equal rows** (`display: flex; flex-direction: column; height: 100%` with `margin-block-start: auto` on the card footer/CTA) and `font-variant-numeric: tabular-nums` on live prices/timers so dynamic content never distorts card alignment.
     - Use `scrollbar-gutter: stable both-edges` on `html` for left/right symmetry with classic scrollbars. Default framed content remains `73vw` even on ultra-wide desktops. An optional centered max-width cap (`78rem`–`90rem`) is a **project-specific visual exception**, never a silent violation of the agreed ~13.5% side framing; measure and document the resulting percentages.
2. **Available 2D space first (Inline + Block).** Reason from the **actual layout viewport** (`clientWidth` and `innerHeight`), then the available content region after sidebars/headers/padding/gaps, then the component's containing block. Never use `100vw` for page/section width (causes horizontal scrollbar overflow on low-res Windows/Linux monitors with `17px` classic scrollbars).
3. **Personal Luxury typography & Adaptive Font-Weight signature.** Use the portable user-chosen scale: H1 32->42, H2 22->26, H3 18->19, paragraphs 15, metadata 12-13 (CSS-px equivalents at a 16px root), implemented using `rem` and bounded `clamp()`. Enforce the balanced Arabic weight ramp (`400-700`: H1 `700->600` on small/low-res screens, H2/H3/CTA `600`, body `400`, captions/micro `500` so `12-13px` text stays crisp on `1dpr` screens), set `-webkit-font-smoothing: antialiased` and `font-synthesis-weight: none` to prevent dark-mode halation and faux-bold distortion, and replace extreme Tailwind weights (`font-black`, `font-extrabold`, `font-light`, `font-thin`). Read [references/typography.md](references/typography.md) and `assets/luxury-fluid-typography.css`. **Existing approved typography defines the visual identity, not an exemption from sizing repairs:** map roles to the current font families/tokens; fix confirmed size/weight/line-height hierarchy violations without sweeping global tag selectors or changing typefaces. The portable numeric scale is a starting reference where no project-specific approved type contract exists.
4. **Structural Reflow on Mobile & Tablet (`< 1024px`).** Automatically restructure Desktop-First markup for `< 1024px` screens without waiting for manual user intervention:
   - **Headers/Navbars (`< 768px` mobile only; NEVER on `>= 1024px` PC screens):** keep only the Logo and at most 1-2 compact icon triggers in the top bar; move secondary CTAs ("Login", "List Your Plate", language/profile links) inside the collapsible drawer/menu (`hidden lg:inline-flex`).
   - **Floating/Absolute Overlay Cards (`< 1024px`):** convert `position: absolute` hero preview cards to `position: static` or `relative` in normal document flow (`static lg:absolute`) so they stack cleanly below `< 1024px` while remaining floating on `>= 1024px` (including `1024x600` via proportional `rem` scaling).
   - **Content-card Grids (`< 640px`):** enforce one-column cards where measured card min-width, wrapping, or readability demands it (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`); compact badges, stats, paired controls and intentional icon matrices MAY retain 2 columns when demonstrated usable and approved. Never rewrite every `grid-cols-2` globally. Preserve the exact approved >=1024px column count.
   - **Horizontal Steppers/Timelines (`< 768px`):** convert horizontal multi-step flows into vertical stacked timelines (`flex-col md:flex-row`), and link desktop connector lines via flex/grid percentages or `rem` instead of fixed pixel widths.
   - **Floating Action Buttons (WhatsApp/Store badges):** reserve bottom clearance on the footer/page (`padding-block-end: clamp(4.5rem, 10dvh, 6rem)`) so fixed bottom badges never cover footer text.
5. **Preserve user-approved visuals while fixing structure.** Do not recolor, rebrand, or change stylistic direction autonomously. Preserving visuals means keeping the exact desktop look and side-whitespace proportions on `>= 1024px` screens (scaled proportionally in `rem`) while adding responsive classes (`flex-col lg:flex-row`, `grid-cols-1 sm:grid-cols-2`, `static lg:absolute`) for `< 1024px` screens.
6. **Mobile & Tablet Landscape (`< 1024px` width with `max-height: 500px`).** On rotated phones (`667x375`, `740x360`, `844x390`):
   - Never lock containers to `height: 100vh` / `h-screen`; always use `min-block-size: 100svh` (or `auto`) with `overflow: visible`.
   - Slim down or unstick headers/toolbars when `max-height: 500px` so fixed chrome takes `< 15%` of `window.innerHeight`.
   - Use a compact 2-column horizontal split (`grid-template-columns: 1.15fr 0.85fr`) for heroes/cards and cap media height (`max-block-size: 48dvh; object-fit: contain`), and keep modals/drawers internally scrollable (`max-block-size: 85dvh; overflow-y: auto`).
7. **Zoom is intentional accessibility behavior.** Do not cancel browser zoom via `transform: scale(1 / zoom)` or disabling viewport meta tags.
8. **RTL and localization first-class support.** Verify Arabic mixed with numbers/English, logical `inline`/`block` dimensions (`margin-inline`, `padding-inline`, `inset-inline-start`), and `dir="rtl"`. In RTL, horizontal overflow and negative-margin bleed occur to the **left (`left < 0`)** as well as the right. Never use negative horizontal margins (`-mx-*`) that push containers beyond viewport edges on mobile.
9. **Measure and verify across the full document height.** Run responsive browser audits across desktop (`1920x1080`, `1600x900`, `1440x900`), smaller PC/laptop screens (`1366x768`, `1280x720`, `1024x600`), tablet portrait/landscape, and mobile portrait/landscape. Inspect both left and right viewport edges (`rect.left < 0` and `rect.right > vw`) and verify desktop side-whitespace framing across all sections.
10. **Explicit permission before starting development servers.** Reuse the project's existing, verified local development URL when available. **Never start, restart, stop, replace, or spawn another local server or background process without first explaining the command, port, purpose, and impact and obtaining the user's explicit approval.**
11. **Prove internal fluidity under real breakpoint conditions.** For nested components (carousels, auction cards, plate visualizers), run `component_audit.py` with both isolated container widths and `--sync-viewport`. Read [references/component-level-qa.md](references/component-level-qa.md).
12. **Evidence-driven acceptance.** Never claim that all screens pass without recording tested component widths, viewport widths (including `1024x600`, `1366x768`, and mobile landscape), and remaining manual tests.

## Workflow (mandatory order)

### 1. Inspect

- Identify framework, CSS strategy, typography, tokens, routing, page templates, RTL conventions, active breakpoints, container widths (`max-w-7xl` without `vw` side gutters), and hardcoded `px` values.
- Capture a **baseline** across large desktop (`1600x900`), smaller PC screens (`1366x768`, `1024x600`), tablet (`768x1024`), mobile portrait (`360x640`, `390x844`), and mobile landscape (`740x360`) where browser access allows.
- Load [references/decision-engine.md](references/decision-engine.md) and relevant topic references below **only when needed**.

### 2. Design the Two-Tier 2D layout contract

- **Tier 1 Contract (Desktop Preservation & Side-Whitespace Framing on `>= 1024px`, including `1366x768`, `1280x720`, `1024x600`):** ensure all section content wrappers preserve `~13.5vw` empty margin on each side (`inline-size: 73vw; margin-inline: auto;`), and convert fixed `px` widths, heights, paddings, gaps, and absolute offsets into `rem` (`px / 16`).
- **Tier 2 Contract (Mobile & Tablet Reflow on `< 1024px`):** define how each complex desktop section reflows below `1024px` (header drawer threshold, floating cards -> `static lg:absolute`, grids -> `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`, steppers -> `flex-col md:flex-row`, mobile landscape 2-column split).
- See [references/available-space-analysis.md](references/available-space-analysis.md) and [references/responsive-and-zoom.md](references/responsive-and-zoom.md).

### 3. Implement (Verified Contract Repair + Scoped Automation)

- **Enforce every confirmed sizing violation (P0/P1/P2), not merely critical defects.** Start with the baseline and a **per-section contract checklist** (reference sizes, computed type roles, gaps, left/right margins, grids, header actions, zoom, mobile landscape). Each mismatch must be fixed, or have a documented intentional-design/accessibility exception. No silent "optional" mismatches. See [references/mandatory-conformance.md](references/mandatory-conformance.md).
- **Preview `scripts/fluid_codemod.py` as a proposal generator, NOT a proof or blanket fixer:** `python scripts/fluid_codemod.py /path/to/project --json`. Only after manual/browser verification and an explicit reviewed change scope, call `--apply --reviewed` **on specific affected files**. Opt in to `--frame-containers`, `--balance-weights`, or `--reflow-grids` only for the corresponding verified defect. The defaults intentionally preserve existing grids, typography weight and container topology; arbitrary px-to-rem proposals still require review. Never apply the codemod across an entire repo just because it flags a pattern.

- **Apply Desktop Side-Whitespace Framing (`>= 1024px`):** wrap section content inside `w-full lg:w-[73vw] mx-auto` (or `.pf-framed-container` / `.page-shell`) so `12%-14%` empty space is always preserved on both right and left sides on every computer monitor.
- **Convert Desktop-First `px` to `rem` / Fluid Tokens:** replace fixed pixel dimensions on cards, containers, gaps, and offsets with `rem` equivalents (`px / 16`) or `%`/`fr` so the layout responds to root scaling.
- **Apply Tier 1 Proportional Desktop Scaling (`>= 1024px`):** import or merge the 2D root scaling media query from `assets/desktop-first-scale.css` so smaller PC screens (`1440x900`, `1366x768`, `1280x720`, `1024x600`) display the exact desktop composition scaled proportionally in both width and height.
- **Apply Tier 2 Structural Reflow (`< 1024px`):** collapse secondary header buttons into the mobile drawer below `768px` (never at `1024px` or `1280px`), stack multi-column grids to `1fr` below `640px`, set floating desktop hero cards to `static lg:absolute`, and add mobile landscape compact rules.
- Establish or preserve **Personal Luxury typography & Adaptive Font Weights** (`assets/luxury-fluid-typography.css`). See [references/typography.md](references/typography.md), [references/components-and-media.md](references/components-and-media.md), and [references/spacing.md](references/spacing.md).
- **Component-inner fluidity:** use declared size-query containers (`container-type: inline-size`), `aspect-ratio`, and `cqi` or SVG `viewBox` for visual artifacts (such as license plates). See [references/component-level-qa.md](references/component-level-qa.md) and `assets/proportional-art-pattern.css`.

### 4. Test and repair

- Run `python scripts/responsive_audit.py --url <actual-project-local-URL> --crawl --real-zoom --strict-review --out ./ui-audit` (or pass `--routes /,/about,/auctions` and `--preset full`) to audit all internal pages, real CSS/root-font zoom (`125%`, `150%`, `200%`), RTL/LTR carousel edge clipping, and desktop `13.5%` side-whitespace framing. Verifies desktop (`1920x1080`, `1600x900`, `1440x900`), smaller PC screens (`1366x768`, `1280x720`, `1024x600`), tablet (`768x1024`, `1024x768`), mobile portrait (`390x844`, `360x640`, `320x568`), and mobile landscape (`740x360`, `667x375`, `844x390`), including desktop side-whitespace checks.
- Run `python scripts/component_audit.py --url <already-running-URL> --selector '<unique-card-selector>' --widths 240,280,320,390,480,600 --sync-viewport --out ./component-audit`.
- Run `python scripts/static_css_audit.py /path/to/project` to inventory potential rigid `px` widths, unframed content containers, mobile content grids, negative horizontal margins, and absolute overlays. **Static findings are review candidates, not automatically confirmed failures.** Triage each, correct confirmed contract mismatches, and explicitly record intended exceptions.
- **Repair -> rerun -> verify** until no verified P0/P1/P2 design-contract nonconformities remain unresolved across tested viewports. Never claim completion solely because browser high-severity findings are zero; typography, spacing, alignment, composition and consistency must also be compared against the approved design/reference.

### 5. Deliver evidence (required conformance ledger)

Report **every detected contract deviation** with page/component, viewport, measured before, target rule, file/property changed, measured after, screenshot proof, and status (`FIXED`, `EXCEPTION with rationale`, `UNVERIFIED`, or `BLOCKED`). Include changed files, validated conversions, left/right margins, desktop preserved column counts, typography/spacing hierarchy, desktop header visibility, zoom tests, and any unresolved or untested cases. The agent MUST NOT label unverified items as PASSED.
